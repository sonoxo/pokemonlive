# 口袋对战实验室

一个无需前端框架的宝可梦单打回合制战斗实验。规则由纯 JavaScript 引擎结算，AI 只负责演出。所有生成的攻击、收回、放出、待机和听令视频采用 2D 宝可梦电视动画风格；像素仅用于 HTML UI 和视频不可用时的本地兜底。默认皮卡丘／小火龙已有本地待机素材；新阵容在放出演出开始播放时并行准备待机、听令和双方各自的收回片。玩家选择招式后，在原战场内播放已准备好的听令特写，后台同时规划与生成攻击视频；没有独立视频弹窗，也不会在视频结束后再次重演像素攻击。

网页 UI 使用独立 `pixel-ui.css`：红黄蓝的复古掌机配色、本地中文像素字体、直角边框和硬阴影。主题只改变 HTML 界面，不将待机／听令／攻击视频像素化；本轮布局验收仅覆盖桌面。字体来源及完整许可见 `THIRD_PARTY_NOTICES.md`。

顶部语言选项支持中文、English、日本語，并在本机记住选择。切换不重开当前战斗；演出期间暂时锁定，避免一段演出中途混用语言。菜单、宝可梦／招式名、日志、规则及分镜摘要随之切换；诊断区的原始生成提示词和 JSON 保留源文，规则结算仍使用原始事实。

新生成的攻击、听令、待机、收回、放出和收尾片均带所选语言的音频约束；喊招使用对应语言台词及 MiniMax 原生音色。三语语音和生成素材分开缓存，中文兼容已有缓存。旧片不会被重新配音；无对白的固定剪影和静音默认待机仍复用。首次切换可能需要生成该语言的缺失素材并产生原有服务费用。语言提示约束不是生成模型绝对遵循的保证；本次只做离线回放与参数验证，未新增付费视频。验证见 `LANGUAGE-VERIFICATION.md`。

## 启动

```bash
npm ci
npm start
```

然后访问 <http://localhost:4173>。

实时像素战场完全使用本地资源；DeepSeek 分镜、fal 视频生成和未缓存的 MiniMax 播报需要联网。

DeepSeek 通过服务端读取密钥，只选择受约束的镜头字段。实时模式给规划 3 秒预算，超过预算则使用本地确定性镜头；最终提示词始终由不可变招式、伤害、速度、先后顺序、异常和濒死记录重建。实时模式每次实际行动使用一个 5 秒段落，整个回合通常为 1–2 段；已有详细分镜协议仍支持决定性动作的扩展结构。镜头强调单次释放、清楚攻击路径和符合技能的受击／非伤害效果，并独立锁定两只宝可梦的形态。

正式生成视频前，在项目根目录创建不纳入源码的 `.env.local`：

```dotenv
FAL_KEY=你的_fal_key
FAL_VIDEO_RESOLUTION=480P
```

视频生成会真实计费。首段优先使用状态匹配的听令／换人尾帧，或上一回合攻击的真实尾帧，通过 `minimax/h3-max-turbo/image-to-video` 接续；没有匹配素材时，使用 `minimax/h3-max/reference-to-video` 和服务端双方非像素角色参考图开场。参考图来自 `assets/video-references/artwork/`，仅锁定物种、颜色及形体，最终统一为手绘动画。后续段严格提取上一段实际尾帧，以 JPEG Data URI 随下一次请求发送，省去独立上传。过渡与首段准备并行；后续片段未就绪则保留上一段尾帧，直到下一段真实首帧解码后切换。攻击演出不再强制使用待机图片作末帧，以保留多机位、受击及持续状态。跳过会取消后续任务，已进入推理的任务仍可能计费。服务端需安装 `ffmpeg`，也可通过 `FFMPEG_PATH` 指定。

当前游戏所有新提交的攻击、换人、待机和听令视频，以及松林素材生成脚本，都使用固定 `seed = 42`（`src/fal-video-runway.js` 的 `FAL_VIDEO_SEED`），不随片段、回合或阵容改变。请求 seed 会进入任务快照、攻击完成埋点和新素材生成记录；它不是服务端回传的确定性保证，也不影响命中、伤害等游戏随机数。[Reference](https://fal.ai/models/minimax/h3-max/reference-to-video/api) 和 [Turbo](https://fal.ai/models/minimax/h3-max-turbo/image-to-video/api) 官方接口均声明支持整数 seed。保持 `balanced` 提示词扩写及尾帧续接不变，不能据此保证不同提示词、输入图和模型的输出完全一致。旧视频缓存及旧生成记录保留原样，未记录 seed 的旧场景返回 `seed: null`，不为此自动重新付费生成；历史弃用的素材实验脚本不属于当前生成入口。

实时演出使用短特写、移动的同场攻击镜头和结果反应镜头，首帧连续不等于全片锁机位。受击强调由真实属性倍率、伤害比例、要害和是否昏厥共同决定；已有／新增状态分别保留。当前没有施加中毒的技能，支持已有中毒的表现；毒伤、灼伤等回合末伤害与行动受阻仍独立结算，不伪装成上一招造成的结果。研究来源、付费样本及限制见 `CINEMATIC-VERIFICATION.md`。

战后收尾保持 5 秒和正常播放速度，采用三镜剪辑：0–1 秒承接真实攻击尾帧的余势，1–2.5 秒单次战后反应特写，2.5 秒直接切回双方同框，最后半秒稳定构图。不再要求慢慢走回原位；低血量用疲态、短促呼吸和小幅调整表现，睡眠、冰冻、昏厥保持原地状态。使用 `battle-recovery-v2` 隔离旧慢拉远收尾，保留旧素材文件，不改变待机／听令缓存或并发链路。代码与回归验证已通过，真实新样片仍待付费授权，不能据此保证模型精确执行切镜时间；见 `RECOVERY-PACING-VERIFICATION.md`。

默认背景使用 `assets/backgrounds/pine-clearing-v2.png`：低机位、松林、草覆岩台的手绘 2D 草地。健康的默认皮卡丘／小火龙待机为 `assets/video/pine-idle-v2-loop.mp4`；听令使用按当前阵容、状态及语言预热的动态素材，旧 `pine-command-v2.mp4` 保留归档。HTML 状态面板独立叠加，演出期间隐藏。其它阵容缺少视频时使用同背景与本地像素精灵，未引入 Three.js。

状态继承使用真实行动前后快照：熟睡角色在后续镜头中保持闭眼和缓慢呼吸，不因普通命中自行醒来；昏厥角色使用卷卷眼并保持倒地。健康、睡眠、冰冻、麻痹、中毒、灼伤、混乱和昏厥不会混用待机缓存；普通 HP 变化不重复生成。

### 三个并发窗口

当真实行动被状态阻止时，也占据自己的行动位置和一个独立 5 秒分镜：麻痹表现局部电弧与僵直；睡眠保持闭眼慢呼吸；冰冻保持完整冰壳；混乱自伤单独表现真实自伤（不是招式反伤），仅在实际倒下时表现卷卷眼。前三类不释放招式、不扣 PP、不产生伤害或解除状态；混乱自伤在视频 2.4 秒同步点应用真实自伤事件。醒来、解冻、成功行动或行动前已经倒下时不会凭状态标签补失败镜头。独立状态片同样使用上一段真实尾帧、固定 seed 和共享下载链路；道具或换人之后的对手受阻也包括在内。增加的状态片会按现有 fal 视频接口产生对应费用，不为旧回合补生成。验证见 `BLOCKED-STATE-VERIFICATION.md`。

1. **招式**：选招后播放本地固定 5 秒训练家喊招剪影片，再接匹配当前阵容、状态和语言的宝可梦听令特写。MiniMax 同时生成／复用本次台词，等剪影真实首帧出现才发声；通常在片内结束，晚到台词最多多保留 1.5 秒尾帧。规划从选招起并行；听令已解码时立即选定其尾帧，规划也完成后即可提交攻击。尚未就绪时在剪影窗口继续预载，解码与规划均完成即可提交，不必等过渡播完。剪影结束时最后检查一次，仍未就绪则锁定原兜底来源，不再为听令额外等待，也不补播迟到素材以免首帧来源错位。后续战斗段保持“上一段真实尾帧 → 下一段首帧”的因果链，不同时提交互相依赖的镜头。训练家视频不进入宝可梦生成参考链。
2. **换人**：我方先播放固定 5 秒训练家举球剪影片，再接收回、放出两个独立片段；对手不插入我方训练家，也不播报对手登场台词。初始入场预热双方收回。匹配的收回素材一旦可用，就在举球期间提交并缓冲放出，不再等收回首帧。放出视频可用后即并发预热新阵容待机、听令、双方收回，不再等其开始播放；后台仍核验并等待实际尾帧。正在等待播放的旧收回槽会被保留，直到放出真实首帧出现才释放，避免新阵容预热覆盖旧片。收回结束后立即接已准备好的放出。收回从真实场景尾帧用 Turbo 生成；放出需要新物种参考，使用 Reference 模型（Image 1/2 新阵容身份、Image 3 收回尾帧、Image 4 环境），提示词要求匹配空场开头，但这不是模型硬约束的首帧保证。首次或未缓存状态允许冷生成收回，始终可跳过。
3. **状态变化**：在最早能代表回合最终状态的攻击片真实首帧播放时，直接并发生成该状态下的待机、听令、收回，不插入额外过渡。服务器只需该片 ready，不等整回合的全部片段；锚点只能引用服务器归档的 sessionId/clipIndex，并核验真实状态。由于攻击可能以单人受击特写收尾，状态素材用 Reference 模型同时接双方身份、真实尾帧与环境参考，重建双方同框；不把特写强行锁成待机镜头。此来源单独使用 `attack-layout-v1` 缓存标记，旧登场来源的已付费素材仍保留复用。KO 攻击期间只预热正确倒地状态的收回，不能为已倒下者买待机；对局结束不预热。生成就绪时即在隐藏播放器中加载，战斗结束无需再重新缓冲。

所有切换都保留上一段，等下一片真实首帧解码后交接。若状态素材比战斗更晚完成，回合照常结束、按钮恢复，匹配尾帧保持可见，素材就绪后接管；不会为等素材持续锁定操作。旧阵容迟到结果不能覆盖当前状态或正在播放的听令。后台最多 5 个执行槽，取消窗口内的新请求先排队，放出优先；同状态缓存与在途请求去重。背景预热会提前产生真实费用（新阵容最多待机、听令、两侧收回各一片），即使玩家随后不使用该动作；失败不会自动重复付费。

当前演出对开场阵容持有临时素材引用，规则提前结算出的下一状态不能取消这些任务；剪影期间保留的听令播放器也不会被未来状态预热覆盖。首段攻击真实首帧接管舞台后释放引用，跳过、失败和重开同样释放；不修改素材缓存键或清理已付费文件。`bridge_ready` / `bridge_unavailable` 埋点记录本次听令选择结果。

从攻击特写重建的待机只取生成视频 1.5–4 秒的稳定中段，正放再逆放制作 5 秒闭环（`settled-mirror-v1`），避免模型开头重新进入状态、结尾镜头漂移反复出现在循环中。该处理只适用于轻微呼吸的待机，不用于听令、收回、放出或攻击。原付费视频保存在同目录 `generation.mp4`，发布的循环视频另行处理，不重复购买。实际角色状态仍需要分帧验收，不能把本地闭环处理当作模型永远遵守状态的保证。旧攻击来源且缺少布局/循环版本的缓存不再可服务，正常登场来源的旧素材不受影响。

动态场景缓存保存在 `.local/scene-videos/`，使用 `pine-state-v2` 隔离旧像素样片；已完成素材可跨服务重启复用。提交前落盘费用意向，提交后记录 fal 请求编号；失败或未确认的旧任务不会自动重新付费提交，需人工核对后恢复。真实样片、桌面回归、计时和审查范围见 `STATE-CONTINUITY-VERIFICATION.md`。

放出动画与旧整段换人使用 `sendout-staging-v2`：我方球从左侧画外进入左侧空位，对方球从右侧画外进入右侧空位；只显示一颗球，投掷时锁定机位与轴线，飞行和局部放出光效避开留场者的整个轮廓，禁止球从其头部／身体出现或与其融合。尾帧仍作为 Reference 模型的场景参考，不是强制首帧；身份、异常状态与并发链路不变。此版本只隔离两种换人缓存，不更改其它素材的键。验证见 `SENDOUT-STAGING-VERIFICATION.md`。

固定训练家素材位于 `assets/video/trainer-command-v1.mp4` 和 `trainer-recall-v1.mp4`：匿名训练家、二维动画剪影，各 5 秒、无音轨，由 `scripts/generate-trainer-videos.mjs` 通过 fal 文生视频各生成一次，运行时只复用本地文件。发生本地读取／解码失败时继续原有特写或战场，不重复生成。生成台账、运行计时与审查见 `TRAINER-CUT-IN-VERIFICATION.md`。

生成脚本：`node scripts/generate-pine-battle-videos.mjs idle` 以新背景及既有动画造型为参考生成 5 秒原片，再局部交叠首尾得到约 4.5 秒循环；人工检查通过后运行 `node scripts/generate-pine-battle-videos.mjs bridge`，以循环首帧生成约 5 秒听令特写并提取真实尾帧。两步新请求会调用 fal 并产生费用；已存请求会恢复查询而不重复提交。旧视频和未通过落地检查的 v1 均保留，但不在页面加载。此次仅验收桌面布局。

### 媒体就绪与复用

攻击片的后续分镜尾帧、状态素材锚点与同源媒体回退共享服务端的一次远端下载与尾帧提取。浏览器优先直接加载 fal 返回的 CDN 视频，服务端同时后台下载归档；CDN 失败或超时后改用同源地址，不重新生成。同源普通 GET / `bytes=0-` 请求可在完整下载前接收视频字节，归档完成后转为本地文件与 Range 服务。CDN 直连意味着浏览器与服务端各自下载，不能理解成总网络流量只有一份。

场景片区分 `playable`、`tailReady`、`archiveReady`：可播放媒体完成即返回客户端缓冲，不再等尾帧和清单归档；依赖尾帧的下一次生成仍等待真实尾帧，攻击来源待机仍先完成闭环加工。底层共享下载和尾帧的验证见 `MEDIA-PIPELINE-VERIFICATION.md`。

### 连续演出提速

借鉴 live-classroom 的状态推送、播放与归档解耦、三播放器预缓冲和分层计时：

- 服务端攻击任务优先订阅 fal 状态流；连接失败或 8 秒无更新时，回退查询同一个 requestId，不重新提交。这里推送的是生成状态，不是未完成视频的流式画面；浏览器到本地服务器仍按现有 300 ms 周期查状态。
- 首段、第二段一旦 ready 就分别在隐藏视频槽解码，不必等听令动画或上一段播放结束才开始加载。首段仍不以第二段就绪为起播条件；已开始的听令动画正常播完。第三个槽用于保留当前帧或媒体恢复，不增加 fal 生成并发。
- 下一段实际首帧到达才隐藏旧视频；续段较慢时保持尾帧。CDN 缓冲、首帧或播放卡顿超时后回退同源媒体；已播放的片段从原进度恢复，不重复触发战斗事件。取消或重开会停止旧演出。
- 新增提交、队列观察、供应商执行观察、结果读取、响应头、首字节、下载大小、解码、片间等待和播放卡顿埋点。`queueWaitMs` / `providerRunMs` 来自状态到达时间，不是精确 GPU 推理耗时。

未改动真实尾帧的生成依赖，也未实现通过 Range 提前提取尾帧；若慢点在服务端完整下载或 fal 排队，此轮不能消除该等待。隔离浏览器案例、测试和速度边界见 `CLASSROOM-SPEED-VERIFICATION.md`。

### MiniMax 训练家播报

系统朗读已替换为 MiniMax `speech-2.8-turbo`，通过服务端 WebSocket 合成。当前音色为「率真弟弟」`Chinese (Mandarin)_Straightforward_Boy`，使用 `happy` 情绪、语速 1.1、语调 +2、合成音量 1.3。浏览器只接收同源 MP3，不接触密钥；我方喊招和换人播报保留，对手「派出了某某宝可梦」只显示文字，不生成或播放语音。

将 `MINIMAX_API_KEY` 设置为服务端环境变量，或写入不纳入源码的 `.env.minimax.local`（也兼容 `.env.local` / `.env`）。已生成音频按音色、模型、参数与台词缓存于 `.local/battle-speech/`，不因状态变化重新合成相同喊招。最多两个不同任务同时生成。写盘失败的成功音频在当前进程有界保留，后续只重试归档；这些未落盘的音频无法跨进程恢复。未缓存语音会真实计费。

## 已实现规则

- 等级 50、IV 31、EV 0、中性性格的能力值计算
- 现代世代核心伤害公式：物理 / 特殊、85–100 随机数、STAB、18 属性相克
- 要害（基础 1/24、倍率 1.5）及对能力阶级的忽略规则
- 能力阶级 −6 至 +6、命中 / 闪避、速度、麻痹减速、招式优先度和同速随机
- 麻痹、灼伤、中毒、睡眠、冰冻与混乱
- PP、招式落空、无效、挣扎与反作用力
- 主动换人、濒死后强制替换、训练家队伍与胜负
- 伤药、万灵药与训练家战不可逃跑

这是规则与交互原型，不包含特性、性格修正、努力值配置、持有物、天气、场地、太晶化、双打规则或完整招式库。源码中的战斗状态机与界面分离，核心规则可由 Node 测试直接验证。

## 项目结构

- `index.html`：语义化战斗界面
- `styles.css`：响应式舞台、状态框、菜单与动画
- `pixel-ui.css`：网页像素主题，不改战斗几何与视频显隐状态
- `src/data.js`：宝可梦、招式、道具数据
- `src/battle-engine.js`：纯 JavaScript 战斗规则与状态机
- `src/attack-storyboard.js`：不可变攻击记录、分镜校验与本地安全降级
- `src/fal-video-runway.js`：fal 服务端队列、严格尾帧续接跑道、取消和短期任务状态
- `src/video-tail-frame.js`：下载 fal 视频并通过 FFmpeg 提取实际最后一帧
- `src/video-media-cache.js`：有界下载共享、尾帧去重和消费者独立取消
- `src/local-video-response.js`：下载期间渐进响应及归档媒体的 Range / HEAD 服务
- `src/visual-battle-state.js`：视觉状态快照、持久状态表演及阵容缓存键
- `src/scene-video-service.js`：分段收回／放出／待机／听令生成、有界并发、本地缓存及防重复付费日志
- `src/attack-scene-anchor.js`：按片读取并核验真实状态尾帧，支持归档恢复及独立取消等待
- `src/scene-video-client.js`：首帧时并行预热、取消和当前阵容素材缓存
- `src/app.js`：DOM 渲染、输入与演出编排
- `server.mjs`：静态资源、DeepSeek 分镜代理与 fal 视频任务接口，保证 API key 不进入前端
- `tests/battle-engine.test.js`：核心规则回归测试
- `tests/attack-storyboard.test.js`：攻击事实、连续锚点和模型输出边界回归测试
- `tests/pixel-battlefield.test.js`：无 Three.js 依赖、本地像素精灵与默认视频回退回归测试
- `tests/fal-video-runway.test.js`：fal 参数、尾帧链顺序、取消与费用前校验
